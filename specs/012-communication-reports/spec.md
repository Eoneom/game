# Slice 012 — Communication reports

**Status**: As implemented on `main` (brownfield). PvP evidence updated after slice [`024`](../024-player-combat-pvp/spec.md) (O005).

## Summary

Players receive persisted **reports** (exploration, base, rebase, transport, battle) generated by movement/outpost sagas and battle outcomes. HTTP supports list (paginated), get by id, mark read, mark all read, and unread count. Old read reports are deleted by a scheduled cleanup job.

**Depends on**: movement outcomes ([`010`](../010-troop-movement-combat/spec.md)). **Out of scope**: in-game chat or player-to-player messaging.

## Battle reports (024)

When a battle finishes, `createBattleReports` writes **two** inbox rows in one transaction — one for the attacker, one for the defender — each with a `report_battle` metadata row (`ReportBattleMetadata`):

| Report field | Attacker row | Defender row |
| --- | --- | --- |
| `troops` | Attacker's cumulative losses | Defender's cumulative losses |
| `resources` | Loot taken (when `outcome.loot_applied`) | Zero |
| `origin` / `destination` | Attack origin → battle cell | Same |

`report_battle` stores perspective, factions, target kind/id, winner, both strategies, `rounds_played`, `outcome_json` (`occupied`, `destroyed_temp_outpost`, `loot_applied`, `attacker_retreated`), per-side casualties and a copy of the per-round summaries (`round_summaries_json`; the live battle keeps its rounds in `battle_round`, see [`010`](../010-troop-movement-combat/spec.md#battle-persistence)). JSON values are serialized before insert because node-postgres would send JS arrays as Postgres array literals, which `jsonb` rejects.

`GET /communication/report/:report_id` adds `battle` (the metadata) for `type = battle`. After both rows commit, `AppEvent.BattleFinished` is emitted per participant with `{ player_id, report_id, perspective, winner }`.

## Web UI

`apps/web/src/modules/communication/` — report list, details (battle branch: factions, strategies, winner, round table, outcome flags, troop lines), translations; inbox route `/inbox/report` ([`019`](../019-web-shell-routing/spec.md)). The selected report is the `?report_id=` search param, so a report can be linked directly.

`communication/ws-listener.ts` shows a « Nouveau rapport de bataille » toast on `battle:finished` with the result from the player's side (Victoire / Défaite / Égalité, `battleResultKind`) and a « Voir le rapport » link to `/inbox/report?report_id=…`. Report list and unread count are refreshed by the troop `ws-listener`.
