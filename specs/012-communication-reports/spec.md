# Slice 012 — Communication reports

**Status**: As implemented on `main` (brownfield).

## Summary

Players receive persisted **reports** (exploration, base, rebase, transport) generated by movement/outpost sagas. HTTP supports list (paginated), get by id, mark read, mark all read, and unread count. Old read reports are deleted by a scheduled cleanup job. Planned PvP adds `battle` report type ([`024`](../024-player-combat-pvp/spec.md)).

**Depends on**: movement outcomes ([`010`](../010-troop-movement-combat/spec.md)). **Out of scope**: in-game chat or player-to-player messaging.

## HTTP

| Method | Path | Auth | Handler |
| --- | --- | --- | --- |
| `GET` | `/communication/report` | yes | `communicationListReportHandler` |
| `GET` | `/communication/report/:report_id` | yes | `communicationGetReportHandler` |
| `GET` | `/communication/report/unread/count` | yes | `communicationCountUnreadReportHandler` |
| `PUT` | `/communication/report/mark` | yes | `communicationMarkReportHandler` |
| `PUT` | `/communication/report/mark-all` | yes | `communicationMarkAllReportsHandler` |

| `CommunicationError` | Meaning |
| --- | --- |
| `communication:report-not-found` | Unknown report |
| `communication:report-not-owner` | Report belongs to another player |

`ReportType` values: `exploration`, `base`, `rebase`, `transport` (`core/communication/value/report-type.ts`).
